# 1.3 package trial

This is a small release-candidate usability check through the actual local stdio
MCP launcher. It is not an accuracy benchmark or an endorsement of the packages.
The cohort contains eight familiar npm packages and three official MCP packages.
They are convenience controls, not independently adjudicated benign samples.
Names were chosen before looking up the versions, and exact versions and registry
integrity were frozen before scans in
[`benchmark/1.3-package-cohort.json`](../benchmark/1.3-package-cohort.json).
No case is removed because of vulnerabilities, an inconvenient verdict or a
failed scan.

## Reproduce

From the candidate checkout, after its runtime files have stopped changing:

```sh
node benchmark/1.3-package-trial.js --self-check
node -p 'require("./src/artifact").BUILD_ID'
node benchmark/1.3-package-trial.js --run <build-id-from-above> /absolute/path/to/new-results.json
```

The output filename must not already exist. The trial checks the build identity
before and after each case and refuses to combine results from different builds.
The manifest hash, source Git commit, runtime build hash, Node/OS, effective
configuration and per-case archive hashes are recorded. Uncommitted runtime
changes are identified by the build hash; the Git commit alone is insufficient.
The harness keeps partial output if an identity assertion or transport failure
interrupts the run. `complete: false` must not be presented as a complete cohort.

The harness launches `bin/mcp-server.js` from a temporary folder with an explicit
empty configuration and removes inherited `PKGXRAY_*` overrides. It verifies the
resulting configuration equals the defaults: `safe-only`, no allowlist or muted
findings, and normal mandatory checks. It invokes
`guard_agent_extension_install` once per pinned package with no overrides, review
decisions, promotion, dependency scan or execution options. A real `initialize`
and `tools/list` exchange precedes the calls. The source files remain inert;
lifecycle scripts and the target MCP servers are never started.

Registry, GitHub, OSV and provenance requests may occur, and existing metadata
caches may be used. Advisory information can change between runs even when the
package and scanner bytes do not. No latency or throughput claim is made.

## Reading the results

- `allow`, `review` and `block` are gate decisions under the recorded policy.
  A review or block is not, by itself, proof of malware or a false positive.
- Known vulnerabilities are retained as findings. Vulnerability-gated packages
  may have source checks skipped; they are not counted as fully scanned.
- Source, dependency, provenance and behavioral coverage are reported separately.
  No direct-dependency scan was requested in this trial.
- A mandatory coverage hold cannot be cleared by an ordinary Proceed decision.
  The summary records whether review is eligible and whether the plan points to
  the user or operator.
- Saved findings contain category/severity counts and bounded relative locations,
  not source excerpts, full metadata, credentials or complete package reports.
- The trial does not establish external tester acceptance, real-world detection
  rates, cross-platform behavior, VM confinement or successful installation.

### Actionability and follow-up

1. **Timeouts need investigation.** Lodash and Zod return a bounded scanner
   timeout instead of a usable report. Neither error is a malware verdict or a
   successful scan. Do not hide these cases or merely raise deadlines to improve
   the reported completion rate.
2. **Source-target inference needs narrowing.** React's diagnostic-looking
   `cjs/MyComponent` target needs syntax-aware review. The three MCP archives'
   `../../.prettierignore` references were checked against integrity-matched
   manifests: they belong to developer `format` / `format:check` scripts, not
   install hooks. The source planner currently records an escape gap even when
   the target is non-mandatory (`mustExist: false`). Any fix must preserve real
   runtime/installation escape and missing-source checks.
3. **The Everything high finding mistakes denylist data for a destination.**
   Reading the exact flagged source as inert text confirmed that `100.64.0.0`
   belongs to a `BlockList.addSubnet` denial table. Same-file outbound fetch
   capability causes the rule to label it as a reached destination. A reduced
   inert denylist-plus-fetch fixture reproduces the high finding; a paired fetch
   to an actual literal address also blocks. This adjudicates the stated finding,
   not the whole package: unresolved flow/lifecycle checks still need review.
   Do not globally exempt addresses or allowlist the package to clear it.
4. **Metadata-only reviews are understandable but add friction.** Picocolors and
   escape-string-regexp have complete requested checks but require user review
   solely for single-maintainer metadata. Their plans correctly point to a
   package-identity review rather than an impossible coverage repair. This is
   product-policy feedback, not a measured false-positive rate.
5. **Mandatory review plans route to the operator.** React and the MCP review
   cases expose coverage reasons and refuse ordinary Proceed. This is accurate
   fail-closed behavior, but a user cannot fix a scanner limitation by rerunning
   unchanged inputs. Documentation should make that distinction clear.

Follow-up runs must use the same frozen 11 inputs and preserve this baseline.
Record a new filename/build identity when runtime changes; never overwrite these
observations or claim the baseline measured the revised scanner.

## Performance and security follow-up

The [controlled performance comparison](../benchmark/1.3-performance-2026-11-17.json)
uses identical, integrity-matched source snapshots and changes only
`src/flow-analysis.js`. With the same 128 MiB old-generation limit, direct static
analysis changed from 30.309 to 21.435 seconds for Lodash and from 49.551 to
27.261 seconds for Zod. These are individual local measurements, not repeated-run
latency guarantees or the full acquisition/MCP journey. Both direct reports
remained REVIEW; non-flow findings were unchanged, while some gap citations
moved as the unchanged analysis limits were reached at different syntax nodes.

In the actual default worker, Lodash changed from a timeout to REVIEW in 28.893
seconds, but Zod still exceeded the unchanged 30-second deadline. Lodash's narrow
margin and Zod's timeout remain reliability concerns even if a separate full
cohort run succeeds. No memory, work, depth or deadline limit was increased.
Independent review found and corrected two exported-alias regressions in an
earlier optimization; the final variant retained credential-export evidence in
17 independently checked alias, closure, default-parameter and prototype cases.

The Everything denylist finding was also narrowed. The
[initial independent review](../benchmark/1.3-ip-policy-review-2026-11-17.json)
found suppression counterexamples; the
[corrected review](../benchmark/1.3-ip-policy-review-followup-2026-11-17.json)
records that those cases again retain their high findings. The exact denylist
source no longer produces the mistaken destination finding, while an added
request to that same literal address still does. This is a file-local syntax
exception, not a package allowlist; imported side effects remain outside that
helper, and whole-package coverage checks remain mandatory.

An [intermediate full-cohort run](../benchmark/1.3-package-results-followup-2026-11-17.json)
on build `4cd3a4edce46b1c9940228a3919d6bba4769f4b2bf036ac25f6da7334dc4eabc`
returned three allow and eight review results, with no block or scan error.
It exposed a remaining collector issue: the file glob in the MCP packages'
`tsc && shx chmod +x dist/*.js` build command caused every script to be treated
as potentially reachable, preserving the spurious formatter-path gap. That
report is retained unchanged. The final run below measures the subsequent
collector refinement on a separately identified build.

## Final candidate follow-up — November 17, 2026

The [final report](../benchmark/1.3-package-results-followup2-2026-11-17.json)
ran from 19:25:30 to 19:26:49 UTC on macOS arm64 / Node 26.0.0, using scanner
build `01dbc36c2b9d5197cbc995ddccb1e57225cf9bb86cca52225e4d6b9f1cafdea2`.
It retained the same 11 frozen inputs, manifest and default `safe-only` policy;
all archive hashes matched the intermediate run. No package code or lifecycle
script was executed, and no policy override or Proceed was applied.

All 11 scans returned assessments: **three allow, eight review, zero block and
zero scan errors**. All 11 vulnerability checks completed with zero reported
CVEs. Direct-dependency scanning was not requested. These results describe the
requested checks in this run, not package safety or independent user acceptance.

|---|---|---|

React's diagnostic `import('./MyComponent')` text no longer creates a runtime
path. The three MCP packages no longer report `../../.prettierignore`: ordinary
file globs in build commands are distinguished from script selectors. Dynamic
or obfuscated selectors, shell/inline evaluation and stdin-driven dispatch stay
conservative, as do actual missing or escaping lifecycle targets. The MCP source
coverage reason is now solely `dist/version.js: computed module specifier`.

The six coverage-held reviews point to operator checks and cannot be cleared by
ordinary Proceed. Picocolors and escape-string-regexp retain the two eligible
metadata reviews. Everything's false denylist-destination block is gone, but its
remaining mandatory holds still prevent approval. No package was allowlisted to
produce these results.

Lodash and Zod both returned REVIEW in this final MCP run. That does not erase
the separate controlled worker measurement in which Zod timed out, nor establish
stable latency under other machines or load. The 600-file cap and incomplete
behavioral modeling remain visible product limits. Independent tester feedback,
fresh release-matrix CI and any intended real VM guest checks remain separate
from this local trial.

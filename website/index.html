A checkpoint before install

Know what you’re
bringing into your project.

Packages and agent tools get real permissions. Add a deliberate check before you give them access.

  1. 01 /
    ↓

    Quarantine the package

    Stage the package in an isolated directory. Normal scans read its files without installing it or running its code.

    guard npm:package@version
  2. 02 /
    ⌕

    Inspect the evidence

    Check package behavior, known vulnerabilities, metadata, and provenance. Fixed rules decide the verdict.

    Every finding cites its source.
  3. 03 /
    ↗

    Make the next call

    Proceed with SAFE, investigate REVIEW, or stop at BLOCK. Only SAFE promotes from quarantine by default.

    The same policy in your CLI and CI.

Read the threat model ↗

npm packages

Behavior + supply chain

Signals of credential theft, suspicious execution, persistence, and prompt injection. Plus known CVEs and npm-to-GitHub artifact checks.

PyPI packages

Focused coverage

Install manifests, known CVEs, metadata, prompt injection, and hidden Unicode. General Python behavioral analysis is not implemented.

MCP servers

Before & during connection

Audit packages and declared capabilities. The runtime proxy gates calls, checks results, and detects manifest drift; it does not track dataflow across calls.

Whole projects

Lockfiles + monitoring

Check npm and Python dependency manifests. Recheck a stored baseline to spot changes in versions and verdicts.

!

A clear boundary. Static analysis cannot clear a payload that only arrives at runtime. Listing MCP tools may launch a server; mcp-proxy runs it, and opt-in canary executes package code in a sandbox. Execution boundaries ↗

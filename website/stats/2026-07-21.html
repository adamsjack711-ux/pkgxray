Methodology & how to reproduce → · Raw JSON · Top-1000 target list

Aggregate calibration on the 1.0.6 engine. packagesScanned counts the distinct popular packages validated this cycle: the top-1000 calibration list, plus two deeper download-ranked sweeps of 1,000 and 3,000 packages that do not overlap. The top-1000 false-block figure is the heuristic count re-measured on the fixed engine (0/1000). Catch rate is measured against the committed corpus of rebuilt known malware, because npm removes live malware and recall against the live registry cannot be tested. The OSV endpoint was unavailable in this run's scan environment, so the results cover heuristics only. That does not affect the false-block metric, which counts heuristic blocks by definition, and known-CVE blocks are true positives by design rather than false blocks.

What the 5,000 counts: 1,000 top-1000 calibration list + 1,000 deeper download-ranked sweep (first) + 3,000 deeper download-ranked sweep (second). Counted separately, not in this denominator: 300 MCP cohort, 21 reconstructed known-malware corpus.

Corrections

Published runs never change. If a number is wrong we publish a new dated run and note it here. We do not edit a number in place. Contest a figure at the tracker.

  • 2026-07-21: Widened validation past the top-1000 calibration list into two deeper download-ranked sweeps of 1,000 and 3,000 packages that do not overlap, to hunt false blocks the head of the list never exercised. The deeper sweeps turned up 16 wrongly-blocked popular packages. 14 were genuine heuristic false positives across six detectors: OID and version dotted-quads read as IP addresses, benign public DNS, HTTP-cookie identifiers read as the browser cookie database, the metaMask web3 connector name read as a wallet read, shell-rc paths named in docs and comments, Sentry's getTransaction read as an on-chain loader, and env and require calls sitting next to each other inside bundled megafiles. The other 2, bun and firebase-tools, do perform the flagged high-risk operation and are recorded as defensible true positives. Every fix relaxes a heuristic, so no fix can cause a new block. The top-1000 calibration list was then re-scanned on the fixed engine (1.0.6): 0 / 1,000 heuristic false blocks, unchanged.
  • 2026-07-26: Metadata-only clarification. No measured number changed. (1) Recorded that engine 1.0.6 (commit 76c0768) was a pre-release build never published to npm, that the public npm release at run time was 1.0.4, and added a commit-checkout reproduction command, since `npx pkgxray@1.0.6` would not resolve. (2) Added the explicit 5,000-package composition: the top-1000 calibration list plus two deeper download-ranked sweeps of 1,000 and 3,000. Recorded that the 300-package MCP cohort and the 21-sample corpus of rebuilt known malware are separate sets, not part of the 5,000 denominator. (3) Noted that the 4,000 extended-sweep targets were selected from the committed download-rank pool, but the resolved snapshot was not committed.
  • 2026-08-11: Copy edit only. No measured number, input list, or source URL changed. Reworded the notes and the earlier entries on this page for plainer language and shorter sentences.
